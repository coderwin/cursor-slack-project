# cursor-slack-project

Cursor와 Slack을 연결하는 봇 프로젝트입니다.

## 작업 진행 규칙

이 저장소에서 작업할 때는 아래 규칙을 따릅니다.

1. **브랜치**: 각 작업마다 별도 브랜치를 만들고, 작업이 끝나면 `main`에 머지합니다.
2. **이슈 · 커밋 · PR**: 작업을 시작하기 전에 이슈를 생성하고, 작업이 완료되면 변경 사항을 커밋한 뒤 PR을 올립니다.

## 작업 방식

이 저장소는 **Slack에서 요청**하고, **Cursor Cloud Agent**가 코드 변경을 준비하며, **GitHub 이슈·PR**으로 이력을 남깁니다.

### 표준 흐름

1. **이슈** — 하려는 일을 GitHub Issue로 등록합니다.
2. **브랜치** — 작업마다 `main`에서 feature 브랜치를 만듭니다.
3. **구현** — 변경 후 README·실행 방법을 함께 갱신합니다.
4. **확인** — 가능하면 로컬에서 실행해 동작을 검증합니다.
5. **PR** — 커밋 후 Pull Request를 열고, 이슈 번호를 본문에 연결합니다 (`Closes #N`).
6. **머지** — 리뷰 후 `main`에 머지하면 작업을 완료로 봅니다.

### 역할

| 구분 | 역할 |
| --- | --- |
| 요청자 | Slack/GitHub에서 목표·범위 전달, PR 머지·우선순위 결정 |
| Cursor Agent | 브랜치·코드·PR 초안, 간단한 실행·HTTP 등 자동 확인 |
| GitHub | 이슈·PR·`main`을 단일 기록(Single source of truth) |

### 주의

- **`main`과 충돌**하는 PR은 충돌 해결 전까지 **머지하지 않습니다**.
- Geolocation 등 브라우저 기능은 **`localhost` 또는 HTTPS**에서만 테스트합니다.
- 기능별 상세 실행 방법은 각 하위 폴더 README를 따릅니다.
